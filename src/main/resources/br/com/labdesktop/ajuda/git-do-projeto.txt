## Mais detalhes
O Git que o app procura é o da pasta do projeto NO SERVIDOR. Se o repositório está só no seu computador ou no GitHub, ele não aparece aqui até ser clonado ou enviado para o servidor: o app ainda não faz isso por você.
Se o repositório do projeto tem configuração que executa programas (um filtro, um fsmonitor, ganchos, um comando de diff), o app avisa e não lê o status nem o diff dele por segurança. O conteúdo de um arquivo com cara de segredo (um .env, por exemplo) só aparece se você clicar em "Mostrar mesmo assim".
Ler o Git nunca escreve nada: a aba Git usa só comandos de leitura, pelo mesmo caminho do Terminal (SSH, inclusive pelo túnel do Session Manager ou da Cloudflare, ou o processo do seu computador). Ela lê quando você abre a aba e quando clica em Atualizar, nunca de tempos em tempos.
O diff mostra "+" nas linhas acrescentadas e "-" nas tiradas, além do tom do fundo, e corta em 2000 linhas por arquivo (o aviso "diff cortado" diz). Arquivo binário aparece como "arquivo binário", sem conteúdo.
Se o Git não está instalado, a linha Código e a aba oferecem "Instalar o Git…", o mesmo fluxo de sempre, com os comandos exatos. Num servidor protegido o app nunca instala nada: o botão fica desligado, mas a leitura continua valendo.
Se o Git recusar a pasta porque ela é de outro usuário, o app mostra a explicação e o comando "git config --global --add safe.directory" com a pasta para você copiar e rodar no Terminal. O app nunca executa esse comando.
Criar o repositório é uma ação de escrita e fica atrás da mesma trava das outras. Antes do clique a janela mostra: se o Git existe, quem assina os commits (se falta, ela pede nome e e-mail e grava SÓ neste repositório, nunca na configuração global), os arquivos que entram, o que fica de fora e as linhas que o app acrescentaria ao .gitignore.
Segredos nunca entram: .env e parentes (.env.local, .envrc), chaves (.pem, .key, id_rsa, .ssh), credenciais (credentials, secrets, .git-credentials, .aws, .htpasswd, .npmrc, tfstate, kdbx, service-account) ficam de fora, em maiúscula ou minúscula, e o app confere com o próprio Git antes de adicionar qualquer arquivo. O .env.example, que é só o modelo, pode entrar. Arquivos com mais de 5 MB ficam de fora, a menos que você marque a caixa.
Uma pasta que já tem o próprio Git (um clone feito à parte, por exemplo) fica de fora do repositório do projeto, com uma linha no .gitignore; a janela explica como guardá-la aqui, se for o caso. O app só cria o repositório local, no branch main, com o commit "Primeiro commit": não faz push, não liga a remoto nenhum e nunca usa --force. Se algo falhar no meio, ele diz o que fez e o que não fez e mostra o comando para desfazer: nunca apaga a pasta .git sozinho.
Muitos projetos guardam o código numa subpasta (a pasta principal tem o docker-compose.yml e o repositório está em app/.git). Quando a pasta principal não tem .git, o app procura repositórios em até 3 níveis de subpastas, sem olhar dentro de node_modules, vendor, .cache, .venv, dist e build, sem seguir links e mostrando no máximo 20. "Trocar repositório" volta à lista. Com um só, a aba abre direto nele; com mais de um, ela mostra a lista com o branch e o último commit de cada um, e o app lembra a sua escolha neste projeto e neste servidor. Só leitura: o app não roda nada de dentro desses repositórios além das mesmas leituras de sempre.
Com repositório numa subpasta, o botão "Criar repositório Git" some da pasta principal: criar um por cima esconderia o histórico dele (o Git trataria a subpasta como um repositório dentro de outro). Fica só o link "Criar um repositório na pasta principal mesmo assim", que abre a conferência com o aviso e uma caixa que você precisa marcar. O app recusa criar nesse caso mesmo que a tela seja contornada: sem a sua confirmação explícita nada é criado.
